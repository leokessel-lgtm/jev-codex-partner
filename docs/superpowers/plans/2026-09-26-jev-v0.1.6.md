# JEV Codex Partner v0.1.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an evidence-driven v0.1.6 compatibility patch for reliable JEV typed responses and clearer gateway diagnostics.

**Architecture:** Probe the raw provider contract with one synthetic all-types request, freeze that structure as an offline fixture, and adapt only the provider boundary while preserving the MCP-facing schema. Keep gateway error classification and release metadata as focused additions around the existing handler.

**Tech Stack:** Node.js 20+, ECMAScript modules, Node test runner, MCP SDK, AJV, Vercel AI Gateway HTTP API.

**Spec:** `docs/superpowers/specs/2026-09-26-jev-v0.1.6.md`

## Global Constraints

- Synthetic data only for live probe and smoke requests.
- No automatic retry, fallback or Choice-to-Boolean decomposition.
- No fuzzy criterion matching or weakening of probability validation.
- Existing tool inputs and result fields remain compatible; additions must be non-secret and additive.
- Existing approval, privacy, fixed-route, credential and advisory-only controls remain unchanged.

## Review Focus

- A raw Choice response names its selection differently from the current fixture: normalise only the field proved by the probe and retain exact allow-listing.
- Score semantics differ from the current zero-based integer assumption: preserve only behaviour confirmed by the probe and reject unsupported shapes.
- Provider confidence is absent or located outside individual answers: treat it as optional and validate it when present.
- A generic HTTP 403 does not mention ZDR: return `gateway_forbidden`, not a false scope diagnosis.
- Successful gateway request identifiers contain unsafe or credential-shaped text: omit or reject them through the existing sanitisation boundary.
