# JEV Codex Partner v0.1.6 Reliability Specification

## Goal

Restore reliable typed JEV evaluation against the live Vercel AI Gateway contract while preserving the plugin's existing governance, authority and privacy boundaries.

## Evidence gate

- Before changing response normalisation, make one synthetic raw `/v1/evaluate` request containing Boolean, Choice and Score questions.
- The request must use the existing fixed model, endpoint and TypeSafe-only routing.
- Record only synthetic response structure and safe provider metadata in a de-identified fixture.
- Let the observed raw response dictate the adapter change. If it does not explain the known Choice failure, stop the compatibility release and investigate rather than forcing the suspected mapping.

## Release scope

- Implement only the adapter changes proved by the synthetic probe.
- Preserve the outward `jev_partner.evaluate` input contract and every existing result field.
- Keep exact criterion allow-listing, type checks, finite probability checks and distribution validation. Do not add fuzzy matching.
- Add specific non-retryable handling for HTTP 403. Use `gateway_zdr_unavailable` only when safe provider detail identifies the known ZDR plan restriction; otherwise use `gateway_forbidden`.
- Preserve the existing generation identifier in `requestId`. Add the already-captured HTTP request identifier as `gatewayRequestId` and add `pluginVersion`.
- Document a manual bounded-Boolean workaround for an invalid Choice response. Never automatically retry, issue a second request or decompose Choice into Boolean questions.
- Release and install version `0.1.6`, then verify the installed cache is byte-identical to the packaged source.

## Deferred

- New doctor or networked ZDR-probe MCP tools.
- Payload hashes or privacy-control fields in default receipts.
- Aggregate input-sizing changes.
- Automatic Choice-to-Boolean conversion.
- Expanded live calibration, cost or latency benchmarking beyond the release smoke test.

## Safety invariants

- Use synthetic data only for probe and smoke requests.
- Keep private/sensitive exact-transfer approval, request-level ZDR, public/synthetic no-training routing, fixed TypeSafe provider routing, credential filtering and advisory-only output.
- Do not transmit locally governed fields that the existing contract keeps local.
- Do not persist raw private requests, responses or receipts.
- Do not expose credential material in output, fixtures, errors or documentation.

## Done when

- Probe-derived Boolean, Choice and Score fixtures pass through the adapter.
- Existing Boolean behaviour remains unchanged.
- Specific 403 tests pass without leaking credentials.
- All existing and new tests, plugin validation, skill validation and repository checks pass.
- Packaged and installed versions are `0.1.6`; installed bytes match the release source.
- One final synthetic all-types smoke request passes after installation.
